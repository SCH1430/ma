# Способы и смысл

Редактируемый источник — `bank.json`: **80 заданий в 10 темах 5–11 классов**.
Это отдельная авторская партия с новыми стабильными ID `methods-…`.
Исходные классовые, экзаменационные и другие тематические банки сохраняются.

| Тема | Класс / программа |
| --- | --- |
| Дроби: действие и обратный вопрос | 5 |
| Проценты и меняющаяся база | 6 |
| Линейное уравнение: структура записи | 7 |
| Неравенства: знак и граница | 8 |
| Квадратные уравнения и границы | 9 |
| ОДЗ: равенство выражений и уравнений | 10, углублённая |
| Функции: значение, аргумент и модель | 10, базовая |
| Геометрия: что меняется при преобразовании | 8 |
| Вероятность: пространство выбора | 9 |
| Выбор модели и границы вывода | 11, базовая |

В каждой теме восемь заданий: **две контрастные пары**, **два задания на
упорядочивание или дополнение решения**, **один переход между представлениями**
и **один случай на границу применимости, вырождение или ограничения**.
Контрастные пары имеют взаимные `relatedIds` и общий `contrastPairId`.
Их отличия содержательны: часть и целое; разные базы процента; неизвестное
в числителе и знаменателе; одно значение корня и два решения уравнения;
одинаковый упрощённый вид при разных исходных ОДЗ.

## Выбор метода и решения

`methods` содержит 32 определения с полями `id`, `title`, `when`,
`limitations`. Задание ссылается на них через `methodIds`, объясняет выбор
в `methodChoice` и математическую цель в `rationale`.

Полное решение состоит из `solutionSteps`: у каждого шага отдельно записаны
`statement` и `reason`. `domain` сохраняет ограничения и допущения исходного
условия; `check` содержит финальную проверку. Поле `solution` объединяет эти
сведения для существующей печати и просмотра. `hint` помогает начать решение.

Каждое задание имеет явные `skills`, `competencies`, `grade`, `level`,
`family`, `revision`. Здесь семейство — редакционная группа задания.
Число групп или определений методов само по себе не является доказательством
числа независимых математических способов. Сложность назначена редакционно;
эмпирическая калибровка по классным результатам ещё не выполнена.

## Форматы ответов

| `kind` | Эталон / смысл |
| --- | --- |
| `number` | Число; точная дробь дополнительно сохранена в `display` |
| `set` | Полный набор действительных корней, включая пустой |
| `interval` | Массив `{lo,hi,loClosed,hiClosed}`; `null` означает соответствующую бесконечность |
| `coordinates` | Пара `[x,y]`; порядок существенен |
| `expression` | `{expression,variables,domain:{excluded}}`, исходная ОДЗ сохраняется |
| `matching` | Объект соответствий; видимые строки — `matchingItems` и `matchingOptions` |
| `steps` | Последовательность ID из `stepOptions`, `responseMode: order` |
| `examples` | Любой ответ, удовлетворяющий именованному математическому валидатору |
| `open` | Рассуждение с 3–4 критериями ручной проверки, без автоматического балла |

Для выражения с сокращением ответ записывается, например,
`x+3 | x!=3`. Для координат — `2;−1`; для сопоставления —
`a-3;b-1;c-2`; для порядка шагов — `s1;s2;s3`.

Четыре конструктивные задачи проверяют равенство дробей, коэффициенты
линейного уравнения с заданным корнем, стороны прямоугольника заданной
площади и количества исходов заданной вероятности. `acceptedExamples`
содержит несколько допустимых образцов; `answerExplanation` прямо указывает,
что список неполон. Остальные допустимые ответы также принимаются.

Модельная задача `methods-models-06` требует самостоятельно назвать
допущение о базе годового процента, дополнить формулу, выполнить расчёт
и указать условие смены модели. При разных допустимых допущениях получаются
11600 либо 11664. Задача `methods-models-08` требует построить контрмодели
для переноса результата опроса одного кружка на всю школу.

## Представления

`representations` содержит только данные локальной визуализации:

- `text`: `caption`, `text`;
- `table`: `caption`, `headers`, прямоугольный массив `rows`;
- `graph`: `caption`, `xLabel`, `yLabel`, `xMin`, `xMax`, `yMin`, `yMax`,
  точки `points: [[x,y]]` и отрезки `segments: [[[x1,y1],[x2,y2]]]`.

`representationLinks` описывает переход `from` → `to` и проверяемый навык.
Графики содержат исходные данные, а не предположительно восстановленный
по тексту чертёж. Таблица квадратичной функции не объявляется доказательством
глобального минимума: в решении дополнительно выделяется полный квадрат.

## Независимые математические проверки

Сборщик `scripts/method_bank_assets.py` не импортирует авторский генератор
или браузерный парсер. Функция `build_method_bank()` возвращает проверенный
словарь с `tasks`, `topics`, `methods`.

В исходнике `mathCheck` задаёт проверяемые математические данные. Независимый
проверяющий код использует точные `Fraction`, операции над коэффициентами
многочленов, перекрёстное умножение рациональных выражений, полный отбор
рациональных корней линейных и квадратных уравнений, включение границ
промежутков, конечный перебор опытов и четыре конструктивных валидатора.
Для порядка шагов проверяются зависимости и сохранение множества решений.
Произвольный Python, вызовы функций кроме точного `sqrt`, атрибуты,
импорты и неограниченные степени запрещены.

Проверка отдельно искажает ответ или свидетельство **каждого из 80 заданий**
и требует отказа. Дополнительно отвергаются опасные AST и оборванные ссылки
контрастных пар. Несколько правильных и неправильных конструктивных примеров
проверяются независимо от формата ввода в интерфейсе.

```sh
python -B scripts/method_bank_assets.py
python -B scripts/method_bank_assets.py --write
```

Первая команда проверяет источник и записывает отчёт
`checks/method-bank-results.json`. Вторая также создаёт
`data/method-bank.js`. Поле `mathCheck` не публикуется в браузер.

## Рецензии и версии

Все задания пока имеют **`editorialStatus: teacher_pending`**.
Внешняя учительская рецензия не утверждается. Сборщик заново рассчитывает
`mathEvidence` после математических проверок. `assistantEvidence` появляется
только для содержания и версии, которые уже явно прочитаны ассистентом
и зарегистрированы в `editorial.json`.
Математическая подпись подтверждает выполненные точные проверки;
она не доказывает автоматически полноту педагогического объяснения.
Ассистентская проверка обозначена как `assistant`, а не как проверка учителем.
Сейчас журнал содержит ровно 80 прочитанных записей первой версии, привязанных
к снимку `revisions/2026-11-methods-r1.json`. Сборщик проверяет контрольную
сумму каждого снимка и не создаёт редакционных одобрений самостоятельно.

`contentHash` — SHA-256 канонического JSON содержимого опубликованного задания
с сортировкой ключей, без `contentHash`, двух свидетельств и
`editorialStatus`. Версия входит в подпись. При редактировании увеличивайте
`revision`, повторяйте математические проверки и сохраняйте статус ожидания
учительской рецензии. Стабильный ID не меняйте.

Порядок исправления и повторного чтения:

1. Измените запись в `bank.json` и увеличьте её `revision`. Изменение
   прочитанного содержания без увеличения версии останавливает сборку.
2. Запустите математическую проверку. У новой версии без записи журнала будет
   свежая `mathEvidence`, но **не будет `assistantEvidence`**. Повторный запуск
   сборки не изменяет этот статус и не переписывает журнал.
3. Отдельно прочитайте исправленные условие, ограничения, способ, каждый шаг
   с обоснованием, подсказку и критерии. Математический проход не заменяет
   это чтение. Только после фактической редакторской проверки можно
   зарегистрировать новое ассистентское свидетельство.
4. Сохраните содержание новой версии в **новый** JSON-файл внутри
   `revisions/`. Структура снимка: `{version: 1, batch, questions: {ID: payload}}`.
   `payload` — опубликованное содержимое задания без `contentHash`,
   `mathEvidence`, `assistantEvidence`, `editorialStatus`; версия входит в него.
   Используйте `contentHash` новой версии из проверенной сборки.
5. **Добавьте** в `editorial.json.records` запись с `id`, `revision`,
   `contentHash`, относительным `snapshot`, датой `recordedOn`,
   `assistant: {status: "assistant_checked", checkedBy: "assistant", note: …}`
   и `teacherStatus: "teacher_pending"`. В примечании опишите реальное чтение.
   Старые записи и снимки не переписывайте. Повтор пары ID–версия запрещён.
6. Повторите сборку. Новое ассистентское свидетельство будет опубликовано
   только при совпадении текущего содержания, версии, записи журнала и снимка.

Отдельные мутационные проверки требуют отказа при правке текста первой версии,
отсутствия ассистентского одобрения у новой непрочитанной версии и сохранения
этого состояния после повторной сборки. Математические проверки при этом
выполняются независимо от наличия редакционной записи.
